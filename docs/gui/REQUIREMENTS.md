# Requisiti e tracciabilità — gui

Requisiti del tool `gui`. I requisiti di progetto e la tabella dei bug sono in [`../REQUIREMENTS.md`](../REQUIREMENTS.md); gli ID `REQ-NNN` sono unici in tutto il repository.

## Requisiti

| ID | Requisito | Stato | File impattati |
|----|-----------|-------|----------------|
| REQ-023 | `gui` deve essere un progetto Cargo autonomo con il proprio `Cargo.toml` in `gui/` (da REQ-001, REQ-003). | implementato | `gui/.gitignore`, `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/main.rs` |
| REQ-024 | `gui` non deve dipendere da codice, crate, configurazioni o file di build di altri tool: niente workspace Cargo condiviso, niente path dependency verso cartelle esterne a `gui/` (da REQ-005). | implementato | `gui/Cargo.toml` |
| REQ-025 | `gui` deve funzionare su Windows 10 e Windows 11. | implementato | `gui/src/main.rs` |
| REQ-026 | `gui` deve essere un server web locale scritto in Rust che serve un'interfaccia web (HTML/CSS/JS) e, all'avvio, la apre automaticamente nel browser predefinito (da REQ-001). | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/main.rs`, `gui/src/server.rs`, `gui/web/app.js`, `gui/web/index.html`, `gui/web/style.css` |
| REQ-027 | `gui` deve offrire più funzioni all'interno della stessa interfaccia, tra cui l'avvio di `doc-ripper`. | implementato | `gui/src/server.rs`, `gui/tests/common/mod.rs`, `gui/tests/ui.rs`, `gui/web/app.js`, `gui/web/index.html`, `gui/web/style.css` |
| REQ-028 | `gui` deve avviare `doc-ripper` eseguendone il binario come processo separato con i parametri `--src` e `--dst`, leggendone output e codice di uscita, senza importare né includere codice di `doc-ripper` (da REQ-005). | implementato | `gui/examples/fake_doc_ripper.rs`, `gui/src/main.rs`, `gui/src/runner.rs`, `gui/src/server.rs`, `gui/tests/common/mod.rs`, `gui/tests/run_doc_ripper.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-029 | `gui` deve cercare `doc-ripper.exe` nella cartella del proprio eseguibile e, se non lo trova, mostrare un messaggio di errore e disabilitare l'avvio di `doc-ripper`. | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/main.rs`, `gui/src/server.rs`, `gui/tests/doc_ripper_lookup.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-030 | La schermata di `doc-ripper` in `gui` deve permettere di scegliere le cartelle di origine e destinazione con un pulsante "Sfoglia" che apre il selettore di cartelle di Windows, aperto dal server perché il browser non fornisce il percorso completo di una cartella. | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/dialogs.rs`, `gui/src/main.rs`, `gui/src/server.rs`, `gui/web/app.js` |
| REQ-031 | Durante l'esecuzione di `doc-ripper`, `gui` deve mostrare in tempo reale l'output prodotto. | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/runner.rs`, `gui/src/server.rs`, `gui/tests/live_output.rs`, `gui/web/app.js` |
| REQ-032 | Al termine dell'esecuzione di `doc-ripper`, `gui` deve mostrare file convertiti, saltati e falliti come riportati nel riepilogo (REQ-017) e se l'esecuzione è riuscita in base al codice di uscita. | implementato | `gui/src/main.rs`, `gui/src/runner.rs`, `gui/src/summary.rs`, `gui/tests/summary.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-033 | Al termine dell'esecuzione di `doc-ripper`, `gui` deve offrire un pulsante che apre la cartella di destinazione in Esplora file e uno che apre `index.md` (REQ-022). | implementato | `gui/src/dialogs.rs`, `gui/src/main.rs`, `gui/src/runner.rs`, `gui/src/server.rs`, `gui/tests/summary.rs`, `gui/web/app.js` |
| REQ-034 | Durante l'esecuzione di `doc-ripper` l'interfaccia di `gui` deve restare utilizzabile e offrire un pulsante "Annulla" che interrompe il processo. | implementato | `gui/src/runner.rs`, `gui/src/server.rs`, `gui/tests/cancel.rs`, `gui/web/app.js` |
| REQ-035 | `gui` deve ricordare le ultime cartelle di origine e destinazione usate e proporle precompilate anche dopo il riavvio del server. | implementato | `gui/Cargo.toml`, `gui/src/main.rs`, `gui/src/server.rs`, `gui/src/settings.rs`, `gui/tests/common/mod.rs`, `gui/tests/settings.rs`, `gui/web/app.js` |
| REQ-036 | Il server di `gui` deve accettare connessioni solo da `localhost` (`127.0.0.1`), così che l'interfaccia non sia raggiungibile da altri computer in rete. | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/src/main.rs`, `gui/src/server.rs`, `gui/tests/common/mod.rs`, `gui/tests/local_only.rs` |
| REQ-037 | `gui` deve fornire uno script di avvio, che avvia il server se non è già in esecuzione, e uno script di arresto, che lo termina insieme a un eventuale `doc-ripper` in corso. | implementato | `gui/start.cmd`, `gui/stop.cmd`, `gui/tests/common/mod.rs`, `gui/tests/quit.rs`, `gui/tests/scripts.rs` |
| REQ-039 | L'interfaccia di `gui` deve offrire un pulsante "Esci" che arresta il server, terminando anche un eventuale `doc-ripper` in corso. | implementato | `gui/src/main.rs`, `gui/src/server.rs`, `gui/tests/quit.rs`, `gui/web/app.js`, `gui/web/index.html`, `gui/web/style.css` |
| REQ-042 | Durante l'esecuzione di `doc-ripper`, `gui` deve mostrare una barra di avanzamento con il numero di file elaborati sul totale e la percentuale, aggiornata in tempo reale dalle righe di avanzamento di `doc-ripper` (REQ-041). (sostituito da REQ-044) | annullato | — |
| REQ-044 | Durante l'esecuzione di `doc-ripper`, `gui` deve mostrare una barra di avanzamento, aggiornata in tempo reale dalle righe di avanzamento di `doc-ripper` (REQ-043), con il file in corso sul totale, per i `.pdf` la pagina in corso sul totale, e la percentuale calcolata dando lo stesso peso a ogni file e, dentro un `.pdf`, aggiungendo la frazione di pagine elaborate (es. file 2 di 2 a pagina 550 di 1100 → 75%). Le righe di avanzamento per pagina servono solo alla barra e non devono comparire nell'output in tempo reale (REQ-031). | implementato | `gui/examples/fake_doc_ripper.rs`, `gui/tests/progress.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-048 | Al termine dell'esecuzione di `doc-ripper`, `gui` deve mostrare nella schermata di `doc-ripper` un'anteprima di `index.md` (REQ-046) della destinazione, con il Markdown reso (titoli e tabella) e i link cliccabili che aprono il file collegato con il programma predefinito. | implementato | `gui/Cargo.lock`, `gui/Cargo.toml`, `gui/examples/fake_doc_ripper.rs`, `gui/src/server.rs`, `gui/tests/index_preview.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-049 | All'avvio di una conversione, e ogni volta che nella destinazione non c'è `index.md` (es. esecuzione annullata o terminata prima della scrittura dell'indice), l'anteprima di `gui` (REQ-048) deve mostrare "Nessun indice disponibile". | implementato | `gui/tests/index_preview.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-069 | `gui` deve offrire, nella stessa interfaccia, una schermata di ricerca che esegue `search-rm3.exe` come processo separato con i comandi `index` e `query` dell'interfaccia comune di `search` (REQ-053), leggendone l'output JSON su stdout (REQ-056) e il codice di uscita (REQ-058), senza importare né includere codice di `search` (da REQ-005). | implementato | `gui/examples/fake_search_rm3.rs`, `gui/src/main.rs`, `gui/src/search.rs`, `gui/src/server.rs`, `gui/tests/common/mod.rs`, `gui/tests/search.rs`, `gui/web/app.js` |
| REQ-070 | `gui` deve cercare `search-rm3.exe` nella cartella del proprio eseguibile e, se non lo trova, mostrare un messaggio di errore e disabilitare indicizzazione e ricerca. | implementato | `gui/src/main.rs`, `gui/src/server.rs`, `gui/tests/search_lookup.rs`, `gui/web/app.js` |
| REQ-071 | La schermata di ricerca di `gui` deve proporre come cartella da indicizzare l'ultima cartella di destinazione usata da `doc-ripper` (REQ-035), modificabile con un pulsante "Sfoglia" che apre il selettore di cartelle di Windows (come REQ-030). | implementato | `gui/tests/search.rs`, `gui/web/app.js` |
| REQ-072 | La schermata di ricerca di `gui` deve offrire un pulsante "Indicizza", un campo per la domanda, un campo numerico per il numero di risultati e un pulsante "Cerca". Il numero di risultati accetta solo interi maggiori o uguali a 1, viene passato a `search-rm3` come `--top`, vale 10 al primo avvio e poi propone l'ultimo valore usato, anche dopo il riavvio del server (come REQ-035). Per ogni risultato devono comparire il file, cliccabile per aprirlo con il programma predefinito, l'intestazione, il numero di riga, il punteggio e il testo della sezione con il Markdown reso. | implementato | `gui/src/search.rs`, `gui/src/server.rs`, `gui/src/settings.rs`, `gui/tests/search.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-074 | All'avvio di una conversione con `doc-ripper`, `gui` deve mostrare in rosso il pulsante "Indicizza" della cartella di destinazione di quella conversione, per segnalare che l'indice va rifatto; il pulsante torna normale solo dopo un'indicizzazione riuscita (codice di uscita 0) di quella cartella. Lo stato deve essere salvato nelle impostazioni di `gui` e restare anche dopo il riavvio del server. | implementato | `gui/src/server.rs`, `gui/src/settings.rs`, `gui/tests/search.rs`, `gui/web/app.js`, `gui/web/style.css` |
| REQ-075 | `gui` deve eseguire `search-rm3`, sia per `index` sia per `query`, passando come `--src` la cartella da indicizzare (REQ-071) e come `--index` la sua sottocartella `.index`, creata se manca; la cartella `.index` non deve essere nascosta. | implementato | `gui/Cargo.toml`, `gui/src/search.rs`, `gui/tests/search.rs` |
| REQ-077 | Ricaricando la pagina, la schermata di ricerca di `gui` deve mostrare di nuovo cartella, domanda, numero di risultati e risultati (REQ-072) dell'ultima ricerca riuscita dall'avvio del server; dopo il riavvio del server la schermata riparte senza risultati. | implementato | `gui/src/main.rs`, `gui/src/server.rs`, `gui/tests/search.rs`, `gui/web/app.js` |
| REQ-078 | La schermata di ricerca di `gui` deve mostrare in rosso il pulsante "Indicizza" (come REQ-074) anche quando la cartella da indicizzare non è mai stata indicizzata, cioè la sua sottocartella `.index` (REQ-075) manca o è vuota; il pulsante torna normale dopo un'indicizzazione riuscita (codice di uscita 0) di quella cartella. | aperto | — |
